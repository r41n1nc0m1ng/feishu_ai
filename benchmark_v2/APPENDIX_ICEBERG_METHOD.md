# Iceberg Construction Method

## 原则

冰山不是 benchmark 主结构，而是**构造 benchmark 的中间方法**。

正确流程：

1. 先定义真实项目、角色、外部约束、交付物
2. 列出群外事件和隐含任务
3. 判断哪些内容会真实投影到群里
4. 只把群里真的会说的话摘成 `messages`
5. 根据隐藏背景写 `expected_brief` 和结构化标准答案
6. 最后剥离冰山层，得到 runtime fixture

## 为什么这样做

- 避免直接让 LLM 生成“为了测试而说的话”
- 让消息具备真实任务压力、角色差异和话题切换
- 更适合构造：
  - 干扰消息
  - 多主题并行
  - 长线更新
  - 长线召回
  - 非程序员协作场景

## 推荐场景池

- 程序开发协作
- 产品边界评审
- 发布运营协调
- 客服/业务口径统一
- 会议组织与会务分工
- 对外路演/答辩准备
- 风险应对与舆情措辞
- 灰度上线与回滚决策

## 生产级 benchmark 规范

- Source 与 runtime 分离
- Source 有统一 schema
- Runtime 尽量贴近原 `full_demo_case` 格式
- 每个 batch 同时有：
  - 可见消息
  - 结构化预期
  - 一句话标准答案
- 覆盖多角色、多任务、多时间跨度
- 覆盖非工程场景，不局限于程序员协作
